\subsection{Cross-dataset generalisation on VeRi-Wild}
\label{sec:veriwild}
A central question for any VeRi-776 result is whether it reflects transferable re-identification ability or tuning to one dataset. To test this, we evaluate our VeRi-776-trained checkpoints zero-shot on VeRi-Wild~\cite{lou2019veriwild} (416{,}314 images, 40{,}671 identities, 174 cameras). We use the identical feature extraction and post-processing, with no fine-tuning. The 174 cameras of VeRi-Wild do not correspond to the twenty of VeRi-776, so we do not remap them. Instead, the Stream~1 camera side-information embedding is fixed to a single constant index for all images. This is one shared camera token, so the SIE offset is identical everywhere and cancels in relative comparisons. Disabling camera and view embeddings is standard practice in cross-dataset ReID evaluation~\cite{benmabrouk2026genlimits}. In-domain on VeRi-776, this substitution costs 2.6\,pp raw mAP (82.30\%$\rightarrow$79.75\%), so it cannot explain the transfer gap reported below. As a further control, we re-ran the transfer evaluation code on VeRi-776 without changes. It reproduces the in-domain trajectory (raw, $+$AQE, both streams) to within 0.1\,pp. We report all three official test protocols (3{,}000\,/\,5{,}000\,/\,10{,}000 identities). Each has equally many queries against 38{,}861\,/\,64{,}389\,/\,128{,}517 gallery images respectively, taken from the official split lists. We exclude same-camera--same-identity matches, as the official protocol requires.
